# TriSeek v0.5.2

v0.5.2 is an MCP memory stability release for large roots with legacy delta indexes.

## Highlights

- `triseek mcp serve` no longer eagerly opens an existing index during startup.
- MCP detects large indexes that would fall back from `fast.idx` to the legacy in-memory `base.bin` plus `delta.bin` path.
- Search and context-pack remain available for those roots by using no-index fallback routing instead of loading the large legacy runtime index inside the MCP stdio process.
- Context-pack skips indexed path-adjacency passes in memory-risk mode so it does not force a full in-process direct scan of very large roots.

## Root Cause

Large central indexes can contain both `fast.idx` and a small `delta.bin`. When a delta exists, `SearchEngine::open` cannot use the mmap fast index and falls back to the legacy runtime index. For a root such as `/Users/trivedi/Documents/Projects`, that path loaded a large `base.bin` and rebuilt postings inside `triseek mcp serve`, causing gigabyte-scale RSS growth before the daemon itself was involved.

## Fix Details

- MCP startup registers the root with the daemon when possible, but does not prime the local cached search engine.
- MCP marks large fast-index-plus-delta roots as memory-risk when searchable bytes exceed `TRISEEK_MCP_LEGACY_INDEX_MAX_BYTES`, defaulting to 512 MiB.
- Search fallback can still read index metadata for routing, so large content searches choose ripgrep instead of direct in-process scans.
- MCP context-pack can run with indexed passes disabled for memory-risk roots while preserving bounded ranked output.

## Migration Notes

No index migration is required. Restart agent clients after upgrading so their MCP server processes use the new binary.

If needed, tune the detection threshold:

```sh
TRISEEK_MCP_LEGACY_INDEX_MAX_BYTES=536870912 triseek mcp serve
```

## Validation

- `cargo fmt --all --check`
- `cargo test -p triseek --test mcp_server`
- `cargo test --workspace --locked`
- `cargo clippy --workspace --all-targets --locked -- -D warnings`

## Runtime Memory Probe

Before the fix, `triseek mcp serve --repo /Users/trivedi/Documents/Projects` reached about 1.6 GiB RSS during initialize and exceeded a 3 GiB guard during one `context_pack` call. After the fix, initialize stayed around 3 MiB RSS and the same guarded `context_pack` call completed with a peak around 382 MiB.
