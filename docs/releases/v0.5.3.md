# TriSeek v0.5.3

v0.5.3 adds privacy-first local usage metrics for agent workflows.

## Highlights

- Added `triseek metrics` with human and JSON rollups.
- Added the MCP `usage_metrics` tool so agents can inspect the same local rollups.
- Metrics are stored per machine under `~/.triseek/metrics/events.jsonl`.
- The default metrics store records private rollups only: no raw query text, absolute paths, file contents, user ids, or network telemetry.
- Search, repeated-search reuse, memo checks, memo sessions, context packs, sessions, snapshots, resumes, handoffs, index status, reindex activity, and reliability errors now contribute to aggregate counters.

## Metric Groups

- Usage: total calls, active days, unique private repo hashes, tool counts, and source breakdowns for CLI, MCP, and daemon events.
- Search value: indexed searches, fallback searches, reuse hits, omitted results, estimated result tokens saved, match totals, and latency percentiles when available.
- Memo value: rereads prevented, memo tokens saved, reads observed, skip rates, stale and unknown detections, tracked files, and compaction invalidations.
- Context and portability value: context-pack usage, token budgets, intents, sessions opened, snapshots, resumes, and handoffs.
- Reliability: daemon unavailable events, index availability observations, reindex counts, and errors.

## Migration Notes

No migration is required. Existing TriSeek state remains valid. New metrics begin accumulating after upgrading and restarting any long-running daemon or MCP server processes.

The metrics file is local to each machine. v0.5.3 does not sync or export metrics across laptops.
