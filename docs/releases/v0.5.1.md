# TriSeek v0.5.1

v0.5.1 is a daemon memory and validation release for long-running agent workflows.

## Highlights

- The daemon now keeps heavyweight search engines lazy, bounded, observable, and evictable.
- Root registration, file watchers, memo state, sessions, snapshots, search reuse, and handoff state remain available without forcing every root's search engine to stay resident.
- Daemon status now reports aggregate and per-root engine load, eviction, and loaded-state counters.
- The context-pack agent smoke harness now runs a real Codex agent against TriSeek MCP tools, with an isolated managed daemon and machine-readable evidence.
- The live agent smoke verifies `context_pack`, `search_content`, and `memo_check` through the same daemon-backed MCP surface agents use.

## Root Cause

The previous daemon memory fix addressed RPC connection and action-log retention, but each registered root still owned a resident `SearchEngine`. Large roots could keep high-heap fast-index structures alive for the daemon lifetime, so a daemon that served multiple large projects could grow substantially over time.

## Fix Details

- `RepoService` now opens `SearchEngine` lazily on search, not during root registration or preload.
- `ServerState` bounds loaded engines with `TRISEEK_DAEMON_MAX_LOADED_ENGINES`, defaulting to 2.
- Loaded engines are evicted by idle timeout via `TRISEEK_DAEMON_ENGINE_IDLE_SECS`, defaulting to 600 seconds, and by least-recently-used pressure when the cache exceeds the configured budget.
- Reloads refresh a loaded engine when needed, but do not force cold roots to load an engine.
- `daemon status` exposes `loaded_engines`, `engine_loads`, `engine_evictions`, and per-root engine counters.
- `context_pack_validation/agent_smoke.py` now supports live `codex` and `claude` harness modes, records agent JSONL, and fails if required TriSeek MCP tool calls do not complete.

## Migration Notes

No index or daemon-state migration is required. Restart the daemon after upgrading so the new bounded engine policy is active.

Optional tuning:

```sh
TRISEEK_DAEMON_MAX_LOADED_ENGINES=2 triseek daemon start
TRISEEK_DAEMON_ENGINE_IDLE_SECS=600 triseek daemon start
```

## Runtime Memory Probe

With `TRISEEK_DAEMON_MAX_LOADED_ENGINES=1`, the release daemon started with zero loaded engines and loaded the large `/Users/trivedi/Documents/Projects` root only on demand. A subsequent TriSeek-root search evicted the large root, leaving `loaded_engines: 1`, `engine_evictions: 1`, and the large root reporting `engine_loaded: false`.
