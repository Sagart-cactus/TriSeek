# TriSeek v0.4.4

v0.4.4 is a Codex installer compatibility release for the current hook configuration model.

## Highlights

- Updated `triseek install codex` for current Codex builds where hooks are stable and enabled by default.
- Fresh Codex installs still write TriSeek Memo hooks to `~/.codex/hooks.json`, but no longer add an unnecessary `codex_hooks = true` feature flag to `~/.codex/config.toml`.
- Existing Codex configs that explicitly disable hooks with `codex_hooks = false` are still corrected during install.
- `triseek doctor`, release smoke tests, and Memo installer docs now treat an omitted `codex_hooks` setting as enabled.

## Root Cause

TriSeek was preserving the older Codex hook model, where `codex_hooks` had to be explicitly enabled in `[features]`. Current Codex documentation lists `codex_hooks` as stable and enabled by default, so writing the flag during every install created unnecessary config churn and made the installer checks assert outdated behavior.

## Fix Details

- `codex_hooks_enabled` now defaults to `true` when the setting is absent.
- The Codex installer skips writing `[features].codex_hooks` for fresh configs.
- If a user has explicitly set `codex_hooks = false`, the installer still writes `codex_hooks = true` so installed hooks can run.
- Doctor output now reports Codex hooks as enabled without requiring the literal feature flag.

## Migration Notes

No migration is required. Existing `~/.codex/hooks.json` files remain compatible.

If your Codex config contains `codex_hooks = false`, rerun:

```sh
triseek install codex
```

The installer will re-enable hooks.

## Validation

- `cargo fmt --check`
- `cargo test -p triseek`
- Isolated temp-home `triseek install codex` checks for both omitted and explicitly disabled `codex_hooks` configs
