# TriSeek v0.5.0

v0.5.0 adds portable `.tcp` handoffs for cross-machine TriSeek sessions, including Git-backed handoff branches for restoring the working tree on another clone.

## Highlights

- `triseek handoff <target> --mode metadata` writes a metadata-only `.tcp` handoff pack.
- `triseek handoff <target> --mode git` creates or uses `triseek/handoff/<session_id>`, commits only when there are uncommitted changes, pushes the branch, and records restore metadata in the pack.
- `triseek resume <handoff.tcp>` imports the pack, restores Git state when present, validates the checkout, and returns the normal hydration payload.
- MCP `session_handoff` can now write `.tcp` packs through `pack_output_path`, with optional Git mode controls.
- MCP `session_resume` now accepts `pack_path` and returns `imported_snapshot_id`, `pack_path`, and `git_restored` when resuming from a pack.

## MCP Changes

- `session_handoff` supports `mode`, `target_harness`, `pack_output_path`, `branch`, `remote`, `message`, and `continue_existing`.
- `session_resume` supports `pack_path`, while preserving `snapshot_id` resume compatibility.
- `snapshot_id` may also be a `.tcp` path for compatibility with clients that only expose the existing argument.

## Git Transport Notes

- The default branch name is `triseek/handoff/<session_id>`.
- Git mode commits only when the source working tree has uncommitted changes.
- Existing handoff branches require `--continue` in CLI or `continue_existing: true` in MCP non-interactive calls.
- Resume stashes local target changes, checks out the recorded handoff branch, reapplies the stash, and flags errors if restore or validation fails.
