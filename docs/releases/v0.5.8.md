# TriSeek v0.5.8

v0.5.8 is a dependency maintenance release. There are no user-facing behaviour
changes; index files, the MCP surface and the CLI all stay compatible with
v0.5.7.

## Highlights

- Refreshed every workspace dependency to its latest compatible release.
- Moved five dependencies across major versions: `notify` 7 to 8, `sha2` 0.10 to
  0.11, `toml` 0.9 to 1.1, `toml_edit` 0.22 to 0.25, and `which` 7 to 8.
- Replaced the deprecated `time::format_description::parse` call in the bench
  harness with `parse_borrowed::<2>`.
- Added `search_core::sha256_hex` so context-pack checksums and server snapshot
  hashes share one implementation, and dropped the now-unused `sha2` dependency
  from `search-cli` and `search-server`.
- Dropped `generic-array` from the dependency graph as a result of the `sha2`
  upgrade.

## Migration Notes

No configuration changes are required.

`sha2` 0.11 no longer returns a digest that implements `LowerHex`, so the two
`format!("{:x}", hasher.finalize())` call sites were rewritten. The emitted
strings are unchanged (lowercase, unseparated hex), so `checksums.txt` files
written by earlier releases still verify, and snapshot hashes stay stable.
A regression test pins that encoding against the standard SHA-256 vectors.

`bincode` is deliberately held at 2.x. The 3.0 release changes the encoding, and
`search-index` still reads a legacy bincode-encoded index as a fallback, so
upgrading would risk making existing on-disk indexes unreadable. That upgrade
needs its own change with an explicit migration path.

`serde_yaml` remains at 0.9.34, which upstream has marked deprecated. Replacing
it is tracked separately.
