# TriSeek v0.5.5

v0.5.5 is a daemon memory stability release for very large workspace roots.

## Highlights

- Skipped daemon filesystem watchers for memory-risk large indexes.
- Kept MCP direct path search on large roots using the low-memory fallback path from v0.5.4.
- Added a regression test proving large index registration does not create a daemon watcher.

## Root Cause

The v0.5.4 MCP path-search fix prevented `find_files` from reading file bodies during large-root fallback searches. A separate daemon path could still register a recursive macOS filesystem watcher for the same large root. On `/Users/trivedi/Documents/Projects`, that watcher could allocate hundreds of MB even when no search engine was loaded.

The daemon now checks index metadata before starting a watcher. If the indexed searchable bytes exceed the daemon watcher threshold, it skips watcher startup for that root.

## Migration Notes

No data migration is required. Restart long-running TriSeek daemon and MCP server processes after upgrading so they use the new binaries.

Advanced users can adjust the watcher threshold with `TRISEEK_DAEMON_WATCHER_MAX_BYTES`.

## Validation

- `cargo fmt`
- `cargo test -p search-server`
- `cargo build --release -p triseek -p search-server`
- Installed-binary repro on `/Users/trivedi/Documents/Projects`: MCP `find_files` stayed near 51 MB RSS, while the daemon stayed under 10 MB RSS after root registration and logged watcher skipping.
