# TriSeek v0.5.6

v0.5.6 is an MCP root-safety release for app-launched agent sessions.

## Highlights

- MCP startup is inert: it no longer builds, refreshes, registers, or watches an index during JSON-RPC initialization.
- Repo-scoped MCP tools now accept an optional `root` argument so app clients can specify the exact folder to search.
- MCP started from `/`, home, or another unsafe implicit location now initializes successfully and returns a structured `ROOT_REQUIRED` tool error until a root is provided.
- Explicit broad roots, including workspace folders like `~/Documents/Projects`, are allowed for direct search but are blocked from reindexing.
- `reindex` is now the only MCP tool path that creates or updates an index.
- Codex install/doctor now uses the current `[features].hooks` flag instead of the deprecated `[features].codex_hooks` flag.
- `triseek install codex` now writes the current `[features].hooks` flag and removes the deprecated `[features].codex_hooks` setting when migrating older configs.

## Root Cause

Codex and Claude app launches can start MCP servers from a process working directory that is not the user session folder. In one failure mode, TriSeek started from `/` and used the old fallback root behavior, which could scan system and home-adjacent paths during startup indexing.

The fix moves root selection from MCP process startup to individual tool calls. Startup can be rootless, search tools can use an explicit root, and unsafe implicit roots no longer trigger filesystem scans.

## Migration Notes

Existing MCP configs continue to work. Agent clients should pass `root` with the smallest project or workspace folder they want TriSeek to search.

Rerun `triseek install codex` if your Codex config still contains `[features].codex_hooks`; the installer now migrates that setting to `[features].hooks`.

Broad explicit roots are direct-search only. To build an index, call `reindex` with a narrower project root.
